# WebDAV 传输

传输层的一个实现：把快照包放到远端，或从远端取回。包格式、校验、计划与落地语义统一见 `10-snapshot-sync.md`；本文只描述 HTTP 侧。

## 1. 边界

| 负责 | 不负责 |
| :--- | :--- |
| 远端目录创建、包的上传/下载/列举/删除、凭据读取 | 决定快照内容、修改 live、加密、多远端、增量索引、断点续传 |

- 只支持 WebDAV，不做 OAuth 类云盘直连，不做 S3 兼容。
- 明文上传。用户选择 WebDAV 即已把信任边界延伸到服务商；不提供半吊子加密（需要时用服务商侧或 rclone crypt 解决）。
- **只允许 HTTPS**（`localhost` / `127.0.0.1` / `::1` 例外）。非 HTTPS 地址在执行时直接拒绝（`remote_insecure`），不发任何请求。保存配置时给 finding 提示，不打断填表。
  - 理由：非 HTTPS 的远端不只是"凭据可能被读走"，更是"可能被塞进任意快照包"，而落地语义是"快照为准"。把整类端点当作不可信，比逐个动作判断更一致。
- 同步单元是**快照包**（一个 zip），不是逐文件。

## 2. 凭据

位置：系统应用数据目录下的 `webdav.json`（与 `backups/` 同级，**不在同步文件夹内**），权限 `0600`，原子写入。Windows 无 POSIX 权限位，改为依赖用户配置目录的默认 ACL（仅本用户与管理员可读）。

| 字段 | 必选 | 说明 |
| :--- | :--- | :--- |
| `url` | 是 | WebDAV 服务地址，如 `https://dav.jianguoyun.com/dav`；只接受 http/https，执行时要求 HTTPS（回环例外） |
| `username` | 是 | 坚果云填注册邮箱 |
| `password` | 是 | 应用密码（可单独吊销），不是账号主密码 |

- 设置页给「坚果云」预设，点选只填地址；其他服务商由用户粘贴地址。
- 保存时空密码 = 保留原值（避免只改地址就把密码清掉）。
- 凭据不进入快照、备份、日志、错误信息与 command 返回值；也不写进同步文件夹（否则会被云盘客户端传走）。
- 明文落盘，UI 必须写明。系统钥匙串不在本期范围（见 `backlog.md`）。

## 3. 远端布局

```text
<url>/PiAgentSync/
├── 20261122-105230-a1b2c3d4.zip
├── 20261121-091210-7f3e9c01.zip
└── .tmp-<纳秒戳>-<fp8>          # 上传中的临时名
```

- `PiAgentSync/` 是常量，不开放配置；地址语义 = 服务地址，不是"云盘里的某个文件夹"。
- 与本地文件夹模式完全同构：同一份包可以用两种方式搬运，校验与落地走同一套代码。
- 只有可解析的包名参与"最新"判定与保留清理；其它文件（`.tmp-*`、旧版目录布局残留、云盘冲突副本、外来文件）一律进"无法识别的文件"。
- 不把同步根设在云盘根目录：坚果云对**根目录下的集合** `DELETE` 返回 403。

## 4. 协议

| 动词 | 用途 | 要点 |
| :--- | :--- | :--- |
| `PROPFIND` | 列包目录 | `Depth: 1`；只取 `resourcetype` / `getcontentlength` |
| `MKCOL` | 建工作根 | 幂等；405/301/302 视为已存在；**不带尾斜杠** |
| `PUT` | 上传包到临时名 | 覆盖同名临时名；目标是一次性的 `.tmp-*` |
| `MOVE` | 临时名 → 正式名 | `Overwrite: F`；失败即停，不降级 |
| `GET` | 下载包 | 404 → 不存在，不抛错 |
| `DELETE` | 删除旧包、清理本次临时名 | 404 视为已删除 |

- **不使用条件请求做并发控制**（`If-Match` / `If-None-Match`）：包名唯一且只增不改，不存在"读远端状态 → 条件写回"这个模式。原先依赖 ETag 的护栏随之取消。
- 超时：控制请求 30s，包传输 120s；不自动重试。
- 认证：HTTP Basic。

### 为什么用 `MOVE` 定案

`PUT` 到正式名会让"半个包"顶着合法名字出现：它会进历史列表、会被"最新"选中、会按较新的时间排在保留队列前面。`MOVE` 把"包在正式名下出现"变成原子事件，是"manifest 落盘即代表快照完整"在包模型下的等价物。

`MOVE` 是 RFC 4918 §9.9 规定的必备方法。**不写"不支持就退回直接 PUT"的降级分支**：那会多一条只在坏服务器上才跑、且安全性更差的通路，违背"不自动降级"。失败就报 `remote_move_failed` 停住，并在错误里带服务器状态码。

失败路径必须清掉本次临时名（`DELETE`，best-effort）；清不掉只记日志，不影响报错本身。

### 服务器差异

| 现象 | 应对 |
| :--- | :--- |
| `PROPFIND` 对不存在的集合返回 207 + 空 body | 原始条目数为 0 即视为不存在 |
| `MKCOL` 带尾斜杠时返回 405 却没创建 | 不带尾斜杠；405/301/302 视为已存在 |
| 云盘根目录不允许 `PUT` 文件 | 写探针放在 `PiAgentSync/` 子目录内 |
| 目录 `DELETE` 需要尾斜杠 + `Depth: infinity` | 仅用于探测清理，失败只记日志 |
| 部分服务商禁止 `DELETE` | 保留清理会失败；按 `remote_prune_failed` 上报，不阻塞上传成功 |
| 下载/上传配额（507，或 403 + 配额提示） | 映射 `remote_quota`，提示流量或空间不足 |
| 请求频率限制（坚果云免费版 600 次 / 30 分钟，与同账号其它第三方应用共用） | 单次同步稳态约 6 个请求；内容未变时只 1 次 `PROPFIND` |
| `PROPFIND` 单次最多列出 750 项 | 保留 20 份，远低于上限；不对列表做分页 |
| 根目录下的集合 `DELETE` 返回 403 | 工作根固定为子目录 `PiAgentSync/`；删的是包文件不是目录 |

**真机实测**（坚果云）：`MOVE` 可用，临时名 → 正式名回 201；`Overwrite: F` 生效，目标已存在时回 409 而不是覆盖；`GET` 返回 `ETag` 响应头；`PROPFIND` 提供 `getetag` 与 `getlastmodified`。第 5 节的 `MOVE` 定案成立。

## 5. 上传

```text
1. 导出     按 10-snapshot-sync §5 在本机工作区生成快照包
2. 内容未变 完整 fingerprint == 记录的 lastUploadedFingerprint → 跳过，不产生新包
3. 门槛     地址必须是 HTTPS（回环例外），否则 remote_insecure，不发请求
4. 列远端   PROPFIND PiAgentSync/
   ├─ 不存在 → MKCOL 建工作根
   └─ 存在   → 取可解析包名集合
5. 定案     PUT .tmp-<纳秒>-<fp8> → MOVE 到正式名
   ├─ PUT 失败  → DELETE 本次临时名（best-effort）→ 报错
   └─ MOVE 失败 → DELETE 本次临时名（best-effort）→ remote_move_failed
6. 清理     重新 PROPFIND → 按名字倒序保留 20 → 删除其余（见 10-snapshot-sync §2）
   └─ 失败 → 结果里报 remote_prune_failed，不影响本次上传已成功
7. 记录     remote-state.json：包名集合、seenAt、lastUploadedFingerprint
```

- 稳态请求数 ≈ `PROPFIND + PUT + MOVE + PROPFIND + DELETE(k) + PROPFIND`，k 通常为 1 → **约 6 个请求**；末尾这次列举是为了把「清理之后 + 期间他机新推」的真实集合写进本机记录，拿上传前的列表推算会把别人的包当成新包。对比逐文件方案（变更文件数 + 目录数 + 2），这不是同一量级。
- 上传中断不会破坏远端：正式名下要么没有包，要么是完整包。
- 旧包只由保留清理删除，不做"被当前快照引用的文件"这类引用判定（每个包自包含）。

### 5.1 自动上行

托盘常驻时的后台任务复用 §5 的完整上传流程，不另写传输逻辑。

| 项 | 行为 |
| :--- | :--- |
| 触发 | 启动后延迟 60 秒执行一次，之后按配置间隔（10–1440 分钟，默认 30）执行；设置页保存后唤醒重读配置；托盘「立即同步」强制执行一次 |
| 内容 | 默认导出并上传时不包含根级 `auth.json`；设置里显式开启后才包含（HTTPS 已是硬门槛） |
| 方向 | 只上行；不自动下载、不应用 |
| 内容未变 | 完整 fingerprint 与上次成功上传相同 → 不写包（空闲期不堆历史），但仍列举一次：更新 `packages` 与 `seenAt`、把 `diverged` 算出来；`lastUploadedFingerprint` 不动 |
| 云端有本机未见的新包 | **照常上传自己的包**，并在状态里显示"云端有 N 份本机未见的新快照"，等用户手动处理。远端只增不改，不存在"覆盖别人"的风险，因此不再因云端变化而停止上行 |
| 并发 | 与手动上传/下载/应用共用一把操作锁；拿不到锁直接跳过本次，不排队 |
| 失败 | 记录状态与可读原因，不自动重试、不降级 |
| 状态 | 只存内存：`idle` / `running` / `success` / `diverged` / `failed` / `skipped` / `paused`；托盘 tooltip 与设置页展示，不弹阻塞对话框 |

## 6. 下载

```text
1. PROPFIND → 可解析包名集合
   └─ 空 → remote_no_packages
2. 选择   默认名字最大的包；用户可在历史列表里指定任意包
3. 取包   GET <包名>.zip
   ├─ 404 → package_not_found（可能刚被别人清理）
   └─ 体积 > 64 MB（先看 PROPFIND 的 content-length）→ package_too_large
4. 解包   按 10-snapshot-sync §2 安全闸门解到 <应用数据目录>/staging/<包名>/
5. 之后完全复用 10-snapshot-sync §6：校验 → 计划 → 预览 → 备份 → 应用
6. 成功后记录 remote-state.json；暂存目录保留当前这一份，更早的清理
```

- 任一步失败删除本次暂存目录，本机 live 不动。
- 状态查询 = 1 次 `PROPFIND`；不做定时轮询。
- 下载不改动远端：不清理、不删除、不写任何文件。

## 7. 状态判定

本机记录：应用数据目录下的 `remote-state.json`，非密钥，只保存**上次成功上传或下载时看到的远端包名集合**与时间：

```json
{ "seenAt": "2026-11-22T10:52:30Z", "packages": ["…", "…"], "lastUploadedFingerprint": "…" }
```

| 远端包集合 | 本机记录 | 判定 | 可用动作 |
| :--- | :--- | :--- | :--- |
| 空 | 任意 | 首次上传 | 上传 |
| 非空 | 缺失 | 保守：提示"云端有包，是否拉取" | 下载 / 上传 |
| 非空 | 相等 | 无人改过 | 上传 / 下载 |
| 非空 | 有新增 | 云端有更新 | 下载（默认最新）/ 选历史包 |
| 非空 | 仅减少 | 别人做了保留清理 | 静默更新记录，不提示拉取 |

- **不用"最大包名"判"有无更新"**：名字里的时间戳来自各机本地时钟，时钟偏慢那台推的新包名字更小，用最大名字比对会漏报。集合比对与时钟无关。
- **最大包名只作默认选中项**，不参与任何安全判定。
- 判定只认可解析名，否则一次失败上传留下的 `.tmp-*` 会让"云端有更新"永久为真。
- 写入时机固定：**上传 → 清理 → 记录**（反过来会把"别人清理了旧包"在下次检查时算成变化）；下载成功后记录。
- `remote-state.json` 缺失或无法解析（换机器、换地址、旧版本遗留）按"无记录"处理，表现是一次保守确认，不丢数据。

## 8. 失败码

见 `10-snapshot-sync.md` §9 的统一表。WebDAV 侧共有 `remote_not_configured`、`remote_unreachable`、`remote_auth_failed`、`remote_quota`、`remote_insecure`、`remote_no_packages`、`package_not_found`、`remote_move_failed`、`remote_prune_failed`。

## 9. 已知限制

- 不做断点续传、不做限流退避、不做增量索引：每个包全量上传。
- 不做多远端、不做多 profile（manifest 已预留 `profileId`）。
- 保留清理只在后台上传/手动上传后进行；只下载从不清理的用户会让远端包数停在历史峰值。
- 不做 PROPFIND 分页：依赖"保留 20 份 << 750 项上限"这一前提。
- 暂存目录保留最近一次下载（计划与应用需要读它），不是用完即删。
- `.tmp-*` 残留只在同一次操作的失败路径里被清除；进程被杀留下的孤儿不会自动老化（见 `backlog.md`）。
- 服务商频率限制未做专门处理；稳态每次上传约 6 个请求，内容未变时 1 个。
