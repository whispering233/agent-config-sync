# 总体设计

## 1. 产品定义

一个桌面工具，把 Pi CLI 的用户级配置变成**可校验的快照**，并在另一台机器上**安全落地**。

- 目标用户：在多台机器上使用 Pi 的个人开发者（自用起步）。
- 核心价值不是"传文件"（云盘已经能做），而是：**传过去的东西对不对、密钥有没有漏、装完能不能跑**。
- 当前实现只面向 Pi；架构上以"宿主适配器"预留其他 agent。

### 非目标（v1）

- 不做实时监听与自动应用：不监听文件系统、不自动下载/应用、不做冲突自动合并；提供可选的托盘常驻与定时自动上行（见 Q3）。
- 不做 agent 运行时能力：本地路由、代理、用量统计、会话管理一律不做。
- 不做多 agent 适配、不做项目级 `.pi` 配置、不做多 profile（见 `backlog.md`）。
- 不自动安装 Node.js，不自动修改用户的 shell 启动文件。
- 不跨 WSL：Windows 版只管理 Windows 原生环境，不读写 WSL 内的路径，也不在 WSL 内执行命令（理由见 `backlog.md`「已知但不做」）。

## 2. 已定决策

| # | 决策 | 结论 | 关键理由 |
| :--- | :--- | :--- | :--- |
| D1 | 产品形态 | 自研轻量桌面软件，不做 cc-switch 的二次开发 | 竞品未覆盖"环境交付"与"脱敏分享"，且其同步语义只覆盖自己建模过的对象 |
| D2 | 传输层 | 双传输并存：本地文件夹（云盘客户端负责"文件到达"）与 WebDAV 直连（应用自己搬运）；两者共用同一套快照与 manifest | 本地模式零协议成本、可离线；WebDAV 去掉"必须装云盘客户端"和"无法得知同步状态"两个前提 |
| D2b | 落地语义 | 快照为准；删除需逐项确认；覆盖前自动备份 | 配置变更是正常行为，删除要可见可控 |
| D2c | 符号链接 | 重建链接优先；目标缺失回退物化并告警；快照未声明的链接只删链接本身；`auth.json` 例外，只按普通文件落地 | 保留集中管理 skills 的布局，避免写穿链接；凭据不指向范围外 |
| D2d | 远端冲突 | 以 manifest 的 `fingerprint` 为基准，本机只记"上次看到的远端 manifest"；manifest 最后写并带条件请求；冲突时按文件清单比对，由用户选择下载或覆盖；远端旧文件不自动删除 | 不依赖时钟与服务器特性；删除必须显式确认 |
| D2e | WebDAV 凭据 | 应用数据目录下单独的 `webdav.json`（POSIX 0600；Windows 依赖继承 ACL），只存地址/用户名/应用密码；不进快照、日志、错误信息与同步文件夹 | 与宿主密钥分离；不引钥匙串依赖；应用密码可单独吊销 |
| D2f | `auth.json` | 纳入快照；整文件覆盖，不按 provider 合并；落地时 POSIX 权限 `0600`，快照目录 `0700` | 与"快照为准"一致；本机独有登录由覆盖前备份兜底；OAuth 多机共享的失效风险在 UI 明示 |
| Q3 | 触发方式 | 手动双向：`上传快照` / `从快照应用`；另提供可选的托盘常驻与定时自动上行，只上传、不自动下载/应用 | 本地模式下云盘无"同步完成"信号；自动应用会绕过删除确认与 `plan_stale`，因此不自动化 |
| Q4 | 密钥处理 | 明文自包含：快照原样保存配置文件，包含 `auth.json`；不再做密钥引用化与环境变量回写 | 让 Pi 需要的东西自包含；云盘/WebDAV 的明文风险由用户知情选择，传输强制 HTTPS（localhost 例外） |
| Q5 | 技术栈 | Tauri v2 + React + TypeScript + Tailwind + shadcn/ui | 体积小；Rust 侧原生处理文件/进程；与项目样式规则一致 |
| Q6 | 宿主安装 | 官方 installer 无 TTY 子进程；npm 全局安装作为降级；Windows 仅走 npm；不引入 PTY | 官方 installer 会 pin 依赖；无 TTY 时行为确定；Windows 版有静默安装 Portable Git 的风险 |
| Q7 | 配置套数 | v1 单套；manifest 预留 `profileId`，快照根目录参数化 | 多套配置是本机问题，不是同步问题 |
| Q8 | 平台顺序 | Linux → Windows → macOS | 开发机即验证机；Windows 有 installer/Git 副作用；macOS 需签名公证 |
| Q9 | 包对齐 | 只安装"已启用且缺失"的声明包；多余包只展示，不自动移除 | 移除包的影响面大于安装，交给用户判断 |

## 3. 能力边界

| 优先级 | 能力 |
| :--- | :--- |
| **P0** | 环境检测（只读探测）、宿主安装/升级、快照导出、快照校验与预览、落地应用、明文密钥扫描与告警、备份与回滚、冲突文件扫描、WebDAV 传输（复用同一套快照/manifest） |
| **P1** | 托盘常驻与定时自动上行（只上传）、产品图标、包版本对齐建议、日志导出与诊断包 |
| **P2** | Pi/插件最新版本显示、分享包（脱敏导出/导入）、多 profile、项目级 `.pi`、隐私地址剥离、系统钥匙串、macOS 分发 |

## 4. 模块划分与数据流

```text
用户
 │
 ├─ UI（React）：环境检测报告 / 快照预览 / 删除确认 / 明文密钥告警 / 日志
 │        │ 只经由 command 调用，不直接访问文件系统
 │
 ├─ 核心（Rust）
 │   ├─ probe      探测 shell / node / npm / pi / 凭据 / 包
 │   ├─ doctor     汇总检查项与建议，只读
 │   ├─ snapshot   白名单收集、写 manifest、计算指纹
 │   ├─ transport  快照搬运：本地文件夹 / WebDAV；远端比对、增量上传、下载到暂存
 │   ├─ verify     manifest 完整性、哈希、格式版本
 │   ├─ plan       与 live 比较，生成新增/修改/删除清单
 │   ├─ apply      重算计划、备份、写入、删除（确认后）
 │   ├─ rollback   备份列表、还原前备份、按 restore.json 反做
 │   ├─ secrets    明文密钥扫描与告警（只读，不改写）
 │   ├─ packages   声明与实装对齐，调用宿主 CLI 重装
 │   ├─ installer  宿主安装/升级（两段式，超时杀进程组）
 │   ├─ tray       托盘常驻、菜单与状态提示
 │   ├─ auto-sync  定时上行调度（只上传，与服务端冲突即停）
 │   └─ conflicts  冲突文件识别与差异摘要（只读）
 │
 ├─ 快照（本地文件夹 或 WebDAV）
 │     snapshot/ + manifest.json
 │
 └─ 本机私有数据（不同步）
       应用配置、备份、日志
```

跨机信息流只有一个方向：`live → snapshot → 另一台机器的 live`。没有实时监听与自动应用；托盘常驻只负责定时上行。

## 5. 核心原则

1. **快照是唯一跨机真相**。live 目录的写入权属于用户与宿主（Pi），本应用只在 apply 时写入受管范围。
2. **远端只是存放处**。本地文件夹与 WebDAV 只负责把同一份快照搬来搬去；校验、计划、落地语义不随传输方式改变。
3. **密钥明文自包含**。快照原样包含 `auth.json` 与配置文件里的字面密钥；不引用化、不回写环境变量。传输必须 HTTPS（localhost 例外），快照目录 `0700`，`auth.json` 落地与快照均为 `0600`。
4. **失败停在原地**。任何一步失败保留备份、不自动重试、不自动降级。
5. **探测与写入分离**。环境检测全程只读；每个修复动作都是用户单独触发。
6. **无数据库、无文件监听**。只有一个应用配置文件、一份凭据、一份远端状态，加上快照 manifest；托盘常驻是可选能力，自动上行只上传，不改变落地语义。同一用户只运行一个实例，第二次启动只唤回已有窗口。
7. **不猜**。版本不兼容、格式不认识、哈希不匹配时停止并说明，不尝试修复。
8. **网络只在明确动作上**。出站网络仅限 WebDAV 传输与用户手动触发的 npm 版本查询；不做后台轮询、不自动重试。

## 6. 主要风险

| 风险 | 影响 | 应对 |
| :--- | :--- | :--- |
| 云盘无"同步完成"信号 | 可能应用半套快照 | manifest 最后写 + 逐文件哈希校验；不匹配直接拒绝 |
| 宿主运行时持续改写配置 | 快照过期、冲突副本堆积 | 只手动导出；导出前提示宿主已退出更稳妥 |
| 符号链接（skills 常见） | 对端技能丢失或坏链 | 物化复制并记录来源；导入时提示重建链接 |
| Pi 配置格式随版本变化 | 解析失败或语义漂移 | 用官方 schema 校验；manifest 记录宿主版本；不兼容即停止 |
| Windows 官方 installer 副作用 | 静默安装 Portable Git | Windows 只走 npm 路径，官方命令仅作展示 |
| 云盘冲突副本 | 垃圾文件与误覆盖 | 冲突扫描 + diff + 人工选择，绝不自动合并 |
| 远端被另一台机器覆盖 | 丢失一次快照 | 上传前比对 fingerprint；manifest 写入带条件请求；冲突要求用户选择 |
| WebDAV 半套上传 | 应用半套快照 | 文件先、manifest 后；下载端逐文件校验，不匹配直接拒绝 |
| WebDAV 凭据泄漏 | 账号被他人使用 | 单独凭据文件（POSIX 0600，Windows 继承 ACL）；不进日志/错误/快照；提示使用可吊销的应用密码 |
| 文件权限/所有权 | `auth.json` 等私有文件被放宽 | `auth.json` 强制 0600；快照目录与备份目录 0700；Windows 依赖用户目录 ACL |
| 明文密钥落入云盘/服务端 | 服务商、版本历史与备份可见 | 导出/应用明示；非 HTTPS 的 WebDAV（localhost 例外）拒绝；不整体加密 |
| OAuth 多机共享 refresh token | 一台刷新后另一台 `invalid_grant`，自动上行可能覆盖云端好凭据 | 文档与 UI 警示；自动上行默认不包含 `auth.json` |

## 7. v1 验收（Definition of Done）

1. 在干净的 Linux 环境上，环境检测能准确报告 node/pi/凭据/包状态，且不写任何文件；Windows 上同一套检查能给出结论。
2. 从一台机器导出快照、经云盘（或 WebDAV）到达另一台，应用后 `pi` 能正常启动，配置一致。
3. 快照可以包含明文密钥；导出与应用都必须给出明确告警，且 `auth.json` 的权限为 `0600`。
4. 删除清单可见、可取消；任何写入前都有可回滚的备份。
5. 任一步失败后，本机配置保持原样（或可一键回滚），并有可读的失败原因。
