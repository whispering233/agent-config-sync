# 开发遗留项

按优先级排列。每项需在开始前补一份设计增量，不直接开工。

## P1

### 包版本对齐

- 动机：快照记录 `requiredPackages`，但不同机器可能装到不同版本。
- 要点：导出时记录已安装版本（读 `pi list` 的安装目录 `package.json`），导入时提示版本差异，允许"按快照版本安装"。

### 日志导出与诊断包

- 动机：用户报问题时需要可读材料。
- 要点：导出脱敏后的日志 + 环境检测报告 + manifest 摘要；不包含配置内容。

### 冲突文件处理（UI + 动作）

- 动机：冲突扫描已能识别与摘要（只读），但用户还不能在界面里处理。
- 前提变化：受管配置不再位于同步文件夹，冲突副本主要出现在**快照包**上（`<包名> (冲突).zip`），落进「无法识别的文件」桶；本项现在只服务「宿主目录自己就在云盘里」的用法。
- 前置：备份能力（已具备）。
- 要点：逐条展示差异，提供"保留原文件 / 用冲突副本替换 / 暂不处理"；动作写入备份目录，绝不自动合并。

### Windows 签名与卸载清理

- 现状：Windows NSIS 自测链路已具备（未签名，安装范围取 `currentUser`）。
- 要点：
  - Authenticode 签名，消除 SmartScreen 首次拦截。
  - 卸载钩子：只在用户主动卸载且明确选择时清理 `%APPDATA%\<identifier>`；必须跳过升级路径（`$UpdateMode`）与静默卸载，删除前用 `config.json` 作归属判据，默认按钮为「否」。
  - 参考实现见本地 `ai-editor` 的 `installer.nsh`（签名文件判据 + `${isUpdated}` / `${Silent}` 双 guard）。

### 回滚时的目录型链接

- 现状：`restore.json` 里 `kind: symlink` 只记目标路径，不记目标是不是目录；回滚按「目标还在不在」推断类型（目标在就用它的类型），建不成链接时按目标物化并告警。
- 目标此刻已不存在时只能按文件链接建，目录型链接会建错类型，随后物化也会失败（没有内容可写）。
- 要点：在备份条目里增加可选的「目标是目录」字段（旧备份缺该字段时按现有推断），或在目标缺失时先试目录链接、失败再试文件链接，二选一。

### macOS 分发

- 动机：Linux/Windows 之外的用户需要安装包。
- 要点：dmg + 签名与公证（需开发者账号）；`~/.local/bin` 不在默认 PATH。
- 注意：Windows 的官方 installer 副作用已在本项目规避（只走 npm），打包不影响该策略。

### 行级文件差异

- 动机：现在只到文件级（路径 + 大小 + 变化类型）。要回答「这个配置文件到底改了哪几行」得自己打开文件。
- 现状：`conflicts` 模块的文本摘要是**逐行对位比较**（不是 LCS），中间插一行会让后面全部算「不同」，差异行数严重高估。
- 要点：引入 `similar`（Apache-2.0）出真正的差异块，用于包 vs live 与包 vs 包的单文件对比；不自研 LCS。
- 触发条件：出现「应用前需要逐行确认某个文件」的真实需求。

### 删除旧格式快照

- 现状：升级前的快照是一个目录，内含 `manifest.json` + `snapshot/`；当前快照是 zip，旧目录布局落进「无法识别的文件」，只展示不处理。
- 判断：这些残留对“最新”判定、保留清理与落地都是惰性的，不处理也没有功能影响。
- 要点：要删的是**目录**，而 `StoreListing.unrecognized` 不带 `is_collection`（`DavEntry` 有，被 store 层丢了），`store.delete` 只删文件；WebDAV 上目录 `DELETE` 还要求尾斜杠 + `Depth: infinity`（坚果云对根目录下的集合直接 403）。
- 前置：先把「不可识别项」带上类型（文件/目录）与体积，再谈目录删除。

### `.tmp-*` 残留老化清理

- 现状：上传失败路径会立即删自己的临时名，但进程被杀/断电留下的孤儿不会自动清，只列在「无法识别的文件」里等用户手动处理。
- 要点：用 `PROPFIND` 的 `getlastmodified` 与服务端 `Date` 响应头算年龄（两端都是服务端时钟，不受本机时钟偏差影响），超过阈值才删；需要给 `PROPFIND` 加一个属性并写 HTTP-date 解析。
- 触发条件：残留真的开始碍事。

## P2

### 快照包重命名与用户标签

- 动机：给重要快照起个名字（如「定稿」），并让它不被保留清理淘汰。
- 要点：改文件名意味着远端 `MOVE` + 本地状态集合比对逻辑跟着变；带标签的份永不自动清理。
- 判断：参考项目为此付出了一整套校验规则，并踩过一次「设备名/tag 恰好等于应用密码 → 密码写进云盘文件名」的事故。除非有明确需求，否则不做。

### 分享包（导出/导入）

- 动机：把配置分享给他人，而不是自己多机同步。
- 形态：复用同一套快照包，增加包内的 `bundle.json`（作者、描述、许可证、可选的 age 加密）。
- 必需：剥离密钥与隐私地址（`baseUrl`、MCP endpoint、`httpProxy`）、导入前逐文件预览、环境要求。
- 前置：本地快照流程稳定；密钥扫描误报率可接受。

### 隐私地址识别与剥离

- 动机：`models.json` 的 `baseUrl`、`mcp.json` 的 `url`、`settings.json` 的 `httpProxy` 可能暴露内网地址。
- 要点：v1 只告警；P2 提供"标记为私有地址 → 替换为占位 → 导入时填写"。识别规则需可编辑，避免误判公共端点。

### 多 profile

- 动机：工作/个人两套配置。
- 要点：`profiles/<id>/` 目录；切换需决定如何让宿主使用该目录（环境变量包装器优先）；密钥按 profile 隔离。
- 前置：manifest 已有 `profileId` 字段。

### 受管根的链接类型

- 现状：根的类型（真实目录/符号链接）不进入快照；根是链接时只同步内容，目标机保留自己的根布局。
- 动机：用 dotfiles 管理 `~/.agents/skills -> ~/dotfiles/skills` 的用户，换机后希望恢复链接而不是真实目录。
- 要点：manifest 记录根的 `kind` 与链接目标；apply 先处理根链接，目标缺失时物化；处理根类型切换与共享目录覆盖确认。

### `settings.skills` 外部路径

- 现状：只盘点并标注“不随快照”，不纳管。
- 动机：用户可能把技能放在 `~/dotfiles/skills` 等任意路径，通过 `settings.json` 的 `skills` 数组引用。
- 要点：需要可配置的外部根 id 与路径映射；不能直接信任 settings 里的绝对路径；与 `~/.agents/skills` 的优先级/冲突要明确。

### 项目级 `.pi` 配置

- 动机：团队共享项目配置。
- 判断：项目配置本来就随 git 走，云同步收益低、冲突高；除非出现明确需求，否则不做。

### 系统钥匙串

- 动机：避免 WebDAV 凭据明文落盘。
- 要点：只存用户主动选择"记住"的条目；钥匙串不可用时降级为不记住。
- 现状：WebDAV 凭据明文存于 0600 文件；`auth.json` 随快照明文同步，不交给钥匙串。

### 其他宿主适配

- 动机：架构上以"宿主适配器"预留。
- 要点：每个宿主需要独立定义受管范围、引用语法、安装路径、凭据检查方式；不在 v1 抽象，等第二个宿主出现再提取。

### 技能盘点的 RPC 输出上限与非 UTF-8

- 现状：技能盘点复用 `run_child_with_input`，读 stdout/stderr 的 reader 用 `read_to_string` 且无上限；遇非 UTF-8 字节时返回错误，只留下出错前的部分内容。
- 后果：宿主输出很大时内存不设限；日志里混入非 UTF-8 字节时表现成「没有响应」，和真的拿不到 `get_commands` 混在一起，看不出原因。
- 要点：reader 加输出上限（参照安装命令的 200 KB 量级）并在超限时告警；改按行读取、非法 UTF-8 走有损解码；解析失败时把「输出不是 UTF-8」单独报出。

### 环境检测未注入生效宿主目录

- 现状：`pi list` 与 `pi auth check` 由探测层直接执行，只有技能盘点会给宿主传 `PI_CODING_AGENT_DIR`。
- 后果：设置里把宿主目录改成非默认值时，包与凭据检查读的仍是宿主的默认目录，与技能盘点、快照的受管根不一致；用户会看到「声明与实装一致」，但导出的是另一个目录。
- 要点：探测层接收生效宿主目录，随每条 `pi` 命令注入（Windows 上按 `cmd` 形态注入环境变量）；或在报告里明写「本次按默认宿主目录检查」。

### 技能盘点与本地导出并发

- 现状：本地文件夹导出不取操作锁（不写 live，也不与其它操作串行），技能盘点则取锁。
- 后果：盘点期间宿主新建的空 `auth.json` 可能恰好落进正在进行的那次导出，导出结果取决于时序。
- 要点：导出也取同一把操作锁，或导出前重扫受管根并比对；不引入排队，也不能把失败降级成重试。

## 已知但不做

- 冲突自动合并（配置文件格式与语义差异太大，猜错代价高）。
- WSL2 内配置托管：Windows 版不读写 `\\wsl.localhost\` 路径、不在 WSL 内执行命令。9P 上建符号链接返回 `ERROR_ACCESS_DENIED`、权限位不可信，支持它要把"链接重建优先"开成例外，并额外引入一层执行环境抽象；收益与改动面不成比例。
- 同步会话、聊天记录、用量统计。
- 本地路由/代理/模型聚合。
- 云端账号体系（不引入服务端）。
