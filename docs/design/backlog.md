# 开发遗留项

按优先级排列。每项需在开始前补一份设计增量，不直接开工。

## P1

### 包版本对齐

- 动机：快照记录 `requiredPackages`，但不同机器可能装到不同版本。
- 要点：导出时记录已安装版本（读 `pi list` 的安装目录 `package.json`），导入时提示版本差异，允许"按快照版本安装"。

### 日志导出与诊断包

- 动机：用户报问题时需要可读材料。
- 要点：导出脱敏后的日志 + 医生报告 + manifest 摘要；不包含配置内容。

### 冲突文件处理（UI + 动作）

- 动机：冲突扫描已能识别与摘要（只读），但用户还不能在界面里处理。
- 前置：备份能力（已具备）。
- 要点：逐条展示差异，提供"保留原文件 / 用冲突副本替换 / 暂不处理"；动作写入备份目录，绝不自动合并。

### Windows 签名与卸载清理

- 现状：Windows NSIS 自测链路已具备（未签名，perUser）。
- 要点：
  - Authenticode 签名，消除 SmartScreen 首次拦截。
  - 卸载钩子：只在用户主动卸载且明确选择时清理 `%APPDATA%\<identifier>`；必须跳过升级路径（`$UpdateMode`）与静默卸载，删除前用 `config.json` 作归属判据，默认按钮为「否」。
  - 参考实现见本地 `ai-editor` 的 `installer.nsh`（签名文件判据 + `${isUpdated}` / `${Silent}` 双 guard）。

### macOS 分发

- 动机：Linux/Windows 之外的用户需要安装包。
- 要点：dmg + 签名与公证（需开发者账号）；`~/.local/bin` 不在默认 PATH。
- 注意：Windows 的官方 installer 副作用已在本项目规避（只走 npm），打包不影响该策略。

## P2

### 分享包（导出/导入）

- 动机：把配置分享给他人，而不是自己多机同步。
- 形态：复用同一套 `snapshot/ + manifest.json`，增加 `bundle.json`（作者、描述、许可证、可选的 age 加密）。
- 必需：剥离密钥与隐私地址（`baseUrl`、MCP endpoint、`httpProxy`）、`requiredSecrets` 清单、导入前逐文件预览、环境要求。
- 前置：本地快照流程稳定；密钥扫描误报率可接受。

### 隐私地址识别与剥离

- 动机：`models.json` 的 `baseUrl`、`mcp.json` 的 `url`、`settings.json` 的 `httpProxy` 可能暴露内网地址。
- 要点：v1 只告警；P2 提供"标记为私有地址 → 替换为占位 → 导入时填写"。识别规则需可编辑，避免误判公共端点。

### 多 profile

- 动机：工作/个人两套配置。
- 要点：`profiles/<id>/` 目录；切换需决定如何让宿主使用该目录（环境变量包装器优先）；密钥按 profile 隔离。
- 前置：manifest 已有 `profileId` 字段。

### 项目级 `.pi` 配置

- 动机：团队共享项目配置。
- 判断：项目配置本来就随 git 走，云同步收益低、冲突高；除非出现明确需求，否则不做。

### 系统钥匙串

- 动机：避免每次导入都手输密钥。
- 要点：只存用户主动选择"记住"的条目；钥匙串不可用时降级为不记住。
- 现状：WebDAV 凭据明文存于 0600 文件；若引钥匙串，两者可共用同一抽象。

### 自动写入环境变量

- 动机：减少手动步骤。
- 风险：修改 shell 启动文件属于高破坏性操作，必须可撤销且默认关闭。

### 其他宿主适配

- 动机：架构上以"宿主适配器"预留。
- 要点：每个宿主需要独立定义受管范围、引用语法、安装路径、凭据检查方式；不在 v1 抽象，等第二个宿主出现再提取。

## 已知但不做

- 冲突自动合并（配置文件格式与语义差异太大，猜错代价高）。
- WSL2 内配置托管：Windows 版不读写 `\\wsl.localhost\` 路径、不在 WSL 内执行命令。9P 上建符号链接返回 `ERROR_ACCESS_DENIED`、权限位不可信，支持它要把"链接重建优先"开成例外，并额外引入一层执行环境抽象；收益与改动面不成比例。
- 同步会话、聊天记录、用量统计。
- 本地路由/代理/模型聚合。
- 云端账号体系（不引入服务端）。
